# Day 68 — Progress Updates

## Upgraded Progress.goalId → Progress.goal (real reference)
type: ObjectId, ref: "Goal", required: true — now a genuine Mongoose 
reference instead of a loose string, enabling populate() and safer queries.

## Current state vs. history
- Goal.progress: a single number, the current snapshot
- Progress collection: a log of entries over time, the full history

## Filtered queries
Progress.find({ goal: goalId }) — narrows results to only matching documents, 
done at the DATABASE level (more efficient than fetching everything and 
filtering in JavaScript).

## Sorting
.sort({ createdAt: -1 }) — descending, newest first.

## Route ordering matters
More specific routes (/api/progress/goal/:goalId) must be registered BEFORE 
more general ones (/api/progress/:id), or Express may match the wrong route.

## How it fits into Decision Journal
A goal's progress can now be viewed as a timeline of updates, not just a 
single current percentage — closer to a real journal's purpose.
