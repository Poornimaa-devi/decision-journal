# Day 85 — Testing Backend APIs

## Why
Manual Postman checks are slow and prove something worked once. Automated
tests re-run the whole check in seconds after every change.

## Kinds of tests
- Unit: one piece alone (errorHandler with a fake error, no database)
- API/integration: real HTTP request through routes, middleware, controllers,
  models and a real database

## Tools
Jest (test runner + expect), Supertest (sends requests straight to the Express
app, no port), mongodb-memory-server (temporary MongoDB, never touches Atlas).

## Structure
Arrange, Act, Assert. beforeAll/afterAll for the database, beforeEach to
create users, clear data between tests so they never depend on each other.

## Why it works
app.js (the app) is separate from server.js (listening) — the Day 39 split.

## Tests must be able to fail
I injected four real bugs (missing user field, no owner check, no $match in
analytics, trusting client-sent owner) and each was caught.

## Ownership tests (two users)
Bob can't read, edit, delete or attach to Alice's data (404, same as missing);
owner always comes from the token; analytics and notifications only count
your own data.

## Gotchas
First run downloads a MongoDB binary; silent: true hides logs (npm run
test:verbose shows them); time-based tests need a small delay.

## How it fits into Decision Journal
The per-user isolation bug from Day 77 is now permanently guarded by tests.
