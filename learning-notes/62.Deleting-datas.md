# Day 62 — Deleting Data (Real DELETE Requests)

## DELETE fetch pattern
fetch(`url/${id}`, { method: "DELETE", headers: { Authorization } })
No Content-Type, no body — DELETE only needs to identify WHICH resource 
to remove, via the URL's id.

## Removing an item from array state
goals.filter((g) => g._id !== goalId)
Creates a new array excluding the matched item — different from Day 61's 
map+ternary (which REPLACES an item; filter REMOVES one).

## Order matters: confirm server success BEFORE updating local state
Only call setGoals(...) after response.ok is confirmed true — prevents 
the UI from showing a deletion that didn't actually happen on the server.

## Full CRUD now complete across the entire stack
- Create (Day 60): POST
- Read (Day 58-59): GET
- Update (Day 61): PATCH
- Delete (Day 62): DELETE
All four now flow: React UI → Express API → MongoDB → back to React.

## How it fits into Decision Journal
The goals feature is now a fully real, persistent, full-stack CRUD 
application — no more local-only or hardcoded data anywhere in the flow.
