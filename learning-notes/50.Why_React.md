# Day 50 — Why React?

## The core problem
As UI grows complex, manually keeping the DOM in sync with changing data 
(imperative style) becomes hard to manage correctly and error-prone.

## Imperative vs Declarative
- Imperative: step-by-step instructions on HOW to update the DOM 
  (what vanilla JS render.js does)
- Declarative: describe WHAT the UI should look like given current data; 
  React figures out how to update the DOM

## What is a component?
A self-contained, reusable piece of UI (like a custom HTML tag), which can 
hold its own data and re-render itself automatically when that data changes.

## Component tree example (Decision Journal)
App → Dashboard → GoalList → GoalCard (repeated per goal)

## How it fits into Decision Journal
The existing vanilla JS dashboard (Phase 2-3) will be rebuilt using React 
components, removing manual DOM manipulation entirely as the app grows 
more complex (Phase 10 features: goals, milestones, reflections, analytics).
