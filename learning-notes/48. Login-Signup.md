# Day 48 — Login & Signup API

## Signup flow
1. Validate email/password presence
2. Check for existing user with that email (409 if found)
3. User.create() — password auto-hashed via Day 45 pre-save hook
4. Respond with hand-picked safe fields only (never the password)

## Login flow
1. Find user by email
2. user.comparePassword() to verify
3. If valid, jwt.sign() to issue a token
4. Send token + safe user info back

## Security practice: vague error messages
Both "no such user" and "wrong password" return the same generic message, 
preventing attackers from discovering which emails have registered accounts 
(user enumeration).

## Why controllers never call bcrypt directly
Hashing happens automatically in the User model's pre-save hook (Day 45) — 
controllers just pass plain passwords to User.create() and let the Model 
handle security internally.

## How it fits into Decision Journal
This is the real entry point for user accounts. Every goal/progress entry 
will eventually be tied to the userId issued here inside the JWT payload.
