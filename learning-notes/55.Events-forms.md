# Day 55 — Events & Forms

## Controlled Components
An input whose value is driven by React state (value={state}), updated via 
onChange, rather than letting the DOM hold its own separate value. Keeps 
state as the single source of truth.

## Key input pattern
<input value={state} onChange={(e) => setState(e.target.value)} />
e.target.value = the current text in the input at that keystroke.

## Form submission
Always call e.preventDefault() in the submit handler — prevents the 
browser's default full-page-reload behavior, essential for React SPAs.

## Passing functions as props
A component (GoalForm) can receive a function from its parent (onAddGoal) 
and call it without knowing what it actually does — decouples the form's 
job (collecting input) from what happens with that data.

## Never mutate state directly
Use setGoals([...goals, newItem]) (spread operator, new array) — NOT 
goals.push(newItem) then setGoals(goals). React needs a new reference 
to reliably detect the change and re-render.

## Rendering lists
array.map((item, index) => <Component key={index} ... />) — key helps 
React track list items efficiently across re-renders.
