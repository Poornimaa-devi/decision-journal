# Day 54 — State

## The problem state solves
Regular JavaScript variable reassignment (count = count + 1) doesn't trigger 
React to re-render — React only "watches" state created via useState.

## useState syntax
const [value, setValue] = useState(initialValue);
- value: current state
- setValue: the ONLY correct way to update it (triggers re-render)
- Array destructuring pulls both out of what useState returns

## Critical rule
Never call the setter immediately in JSX: onClick={setValue(...)} is WRONG 
(runs immediately, causes infinite loops). Always pass a reference or wrap 
in an arrow function: onClick={() => setValue(...)} or onClick={handlerFn}

## Props vs State
- Props: passed IN from parent, read-only
- State: owned BY the component itself, can change via its setter

## Each component instance has independent state
Rendering <GoalCard /> three times creates three completely separate 
completed state values — clicking one never affects the others.

## What is a Hook
A special React function starting with "use" (useState, useEffect later) 
that lets a component access React features. Must be called at the top 
level of a component, never inside loops/conditions.
