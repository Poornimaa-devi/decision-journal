# Day 41 — CRUD with MongoDB

## Mapping old array logic to Mongoose methods
| Array operation | Mongoose method |
|---|---|
| read all | Goal.find() |
| find one by id | Goal.findById(id) |
| add new | Goal.create(data) |
| update existing | Goal.findByIdAndUpdate(id, data, { new: true, runValidators: true }) |
| remove | Goal.findByIdAndDelete(id) |

## Why controllers became async
Every Mongoose method is a network call to MongoDB, returning a Promise. 
async/await lets us pause and wait for the real result instead of assuming 
instant completion like array operations did.

## Why try/catch + next(err)
Database calls can genuinely fail (bad connection, invalid ID, etc). 
try/catch stops the app from crashing; next(err) hands the error to 
errorHandler.js middleware (built on Day 31-32) to send a proper response.

## Key options that matter
- { new: true } → returns the updated document, not the stale pre-update one
- { runValidators: true } → re-applies schema validation rules during updates

## How it fits into Decision Journal
goalController.js now reads/writes real, persistent data in MongoDB Atlas. 
Data survives server restarts — the core problem from Day 36 is solved.
