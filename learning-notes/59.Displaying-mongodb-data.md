# Day 59 — Displaying MongoDB Data (Loading/Empty/Error States)

## Three states of any data-fetching UI
- Loading: fetch is still in progress
- Empty: fetch succeeded, but there's no data
- Error: fetch failed

## isLoading pattern
useState(true) initially, set to false in a finally block — guarantees 
it always resolves regardless of success/failure.

## Nested ternary for conditional rendering
{isLoading ? <Loading /> : error ? <Error /> : empty ? <Empty /> : <RealData />}
Order matters — check loading first, then error, then empty, then real data.

## Spread operator on props
<Component {...object} /> passes every key in `object` as a separate prop — 
shorter than listing each prop explicitly, but passes ALL keys, even unused ones.

## try/catch/finally
finally runs regardless of whether try succeeded or catch caught an error — 
ideal for cleanup logic like "stop showing loading spinner" that must 
happen either way.

## How it fits into Decision Journal
The dashboard now handles real-world conditions gracefully: slow networks, 
empty accounts, and backend downtime — not just the "happy path" of data 
always being instantly available.
