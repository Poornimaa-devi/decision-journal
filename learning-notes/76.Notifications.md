# Day 76 — Notifications

## Computed vs stored
Notifications are calculated from existing goals/decisions on each request —
no Notification model. Same philosophy as derived data (Day 64): don't store
what you can compute. Limit: no read/unread state, no history.

## Date queries
createdAt / updatedAt come from timestamps: true.
{ createdAt: { $lt: cutoff } } → earlier than cutoff.
cutoff = new Date(Date.now() - days * 24 * 60 * 60 * 1000)
$lt = less than, $gte = greater than or equal.

## Promise.all
Runs independent async operations in parallel; results come back in order.
Any rejection makes the whole thing throw (caught by try/catch).

## Testing tip
A ?days= override makes time-based features testable without waiting a week.

## Limitation
Goal.updatedAt doesn't change when Progress entries are logged (separate
collection), so "stale" means "goal not edited."

## How it fits into Decision Journal
Users get nudges about pending decisions, neglected goals, and goals close
to completion — encouraging them to return and act.
