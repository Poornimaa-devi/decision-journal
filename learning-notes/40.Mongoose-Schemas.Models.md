# Day 40 — MongoDB + Mongoose (Schemas & Models)

## What is a Schema?
A blueprint defining what fields a document should have, their types, and 
validation rules (required, enum, min/max, defaults).

## What is a Model?
The usable tool built from a Schema, used to actually create/read/update/delete 
documents in a specific MongoDB collection.

## Schema vs Model
Schema = blueprint | Model = factory built from the blueprint | Documents = products

## Why keep middleware validation AND schema validation?
- Middleware: catches bad input early, before touching the database, custom 
  error messages
- Schema: last line of defense — database itself refuses invalid data, even 
  if middleware is bypassed somehow

## Key Mongoose naming convention
mongoose.model("Goal", schema) → creates a MongoDB collection called "goals" 
(auto-lowercased and pluralized)
