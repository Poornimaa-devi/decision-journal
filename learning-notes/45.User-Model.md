# Day 45 — User Model

## Schema fields
- email: required, unique, trimmed, lowercase
- password: required, minlength 6

## Pre-save hook
Runs automatically before a User document is saved. Checks isModified("password") 
to avoid re-hashing an already-hashed password on unrelated updates (e.g. 
editing email later). If password is new/changed, hashes it with bcrypt 
before saving.

## Why isModified() matters
Without it, every save operation (even unrelated field updates) would re-hash 
the already-hashed password, corrupting it after the first save.

## Why regular function, not arrow function
Arrow functions don't bind "this" the way Mongoose needs inside hooks — 
"this" must refer to the document being saved.

## Custom instance method: comparePassword
Added directly to the Schema so any User document can call 
user.comparePassword(typedPassword) instead of writing bcrypt.compare() 
manually in every controller.

## How it fits into Decision Journal
This is the foundation for signup/login (Day 48). Every goal/progress entry 
will eventually be linked to a specific User via this model.
