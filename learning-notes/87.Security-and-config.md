# Day 87 — Security & Environment Configuration

## Holes I found by attacking my own API
- PATCH with {"$set":{"user":...}} moved a record into another user's account
  (blacklist of "user" missed operators) -> whitelist fields with pick()
- Login with {"email":{"$ne":null}} (NoSQL injection) -> require string types
- ?search=( crashed with 500 (regex injection) -> escapeRegex()
- No rate limit, open CORS, X-Powered-By visible, 3 vulnerable dependencies

## Defenses (defense in depth)
helmet headers, CORS allowlist (CLIENT_ORIGIN), rate limit on FAILED logins,
10 KB body limit, HS256 pinned, whitelist + type checks + owner filter,
errors hidden in production, validateEnv() refuses weak/missing config,
npm audit fix.

## Environment
Secrets only in .env (gitignored). JWT_SECRET >= 32 random chars
(crypto.randomBytes). Rotate any leaked secret; deleting a commit is not enough.

## Still not covered
httpOnly cookies / refresh tokens, email verification, password reset,
account lockout by user, HTTPS (provided by the host), CSRF (not an issue with
bearer tokens, but localStorage is XSS-readable).

## How it fits into Decision Journal
The API now rejects hostile input and is safe to put on the internet.
