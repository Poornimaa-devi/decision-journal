# Day 79 — React Routing

## Why
One-screen app → real URLs: bookmarkable, refresh-safe, working back button.
Replaces Day 66's selectedId workaround for decision details.

## Core pieces (react-router-dom)
- BrowserRouter: wraps the app once (main.jsx)
- Routes / Route path element: URL pattern → component
- Link: navigates without a page reload (<a href> reloads and loses state)
- NavLink: Link with an automatic "active" class; use `end` on "/"
- useParams(): reads URL params (/decisions/:id → { id }), like req.params
- path="*": catch-all for unknown URLs (frontend version of the 404 handler)

## Pages vs components
Page = a component rendered by a route (src/pages). The goals state moved
from App.jsx into GoalsPage; App.jsx is now just layout + routes.

## useParams + useEffect
useEffect(() => { fetch by id }, [id]) — refetches if the URL param changes.

## Gotchas
- State resets when navigating away (pages unmount) — refetch on return
- Production hosting needs a rewrite so all paths serve index.html

## How it fits into Decision Journal
Goals, decisions, insights and profile are separate pages with real URLs,
the foundation for protected routes and the login page (Day 80).
