# Day 69 — Milestones

## Milestone vs Progress vs Goal.completed
- Goal.completed: overall done/not-done flag
- Progress: continuous percentage log over time
- Milestone: discrete, named sub-achievement within a goal

## Schema (built independently, following Decision/Progress patterns)
goal (ObjectId ref "Goal", required), title (String, required), 
completed (Boolean, default false), timestamps

## No new Mongoose concepts today
Reinforced: required references, defaults, full CRUD controller pattern, 
route ordering for nested-style endpoints (/goal/:goalId before /:id)

## Deliberate scope decision
Completing all milestones does NOT automatically complete the parent goal — 
that would require additional logic (e.g., in updateMilestone, checking 
all siblings and conditionally updating the Goal) not built today.

## How it fits into Decision Journal
Goals can now have specific, named checkpoints tracked separately from 
their overall completion status and percentage progress — a more complete 
reflection of how real goals are actually pursued.
