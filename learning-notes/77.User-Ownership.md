# Day 77 — Feature Integration (User Ownership)

## Authentication vs authorization
Authentication = who you are (JWT, Days 44-49). Authorization = what you may
access (today). Every document now belongs to a user.

## Ownership pattern
- Each model has user: ObjectId ref "User", required, indexed
- Owner always comes from the token (req.user.userId), never req.body
- create: { ...body, user: userId } — user LAST so it overrides client input
- update: strip `user` from the body
- read/update/delete: filter by { _id, user } so wrong-owner = not found
- parent checks: before linking to a goal/decision, verify the caller owns it

## IDOR
Insecure Direct Object Reference: letting someone access a record just by
knowing its id. Prevented by always scoping queries to the owner.

## 404 not 403
A wrong-owner request returns the same 404 as a missing document, so ids
can't be probed to find out what exists.

## Aggregation does NOT cast types
find({ user: "id-string" }) works (Mongoose casts). aggregate() $match does
not — convert with new mongoose.Types.ObjectId(userId) or it matches nothing.

## Migration
One-off script claimed existing ownerless documents for my account
(updateMany with { user: { $exists: false } }). Schemas must be updated first
or the $set is silently dropped.

## How it fits into Decision Journal
Multiple users can now share the app without seeing each other's data —
the foundation for any real deployment.
