# Day 44 — Password Hashing

## What is hashing?
A one-way transformation: plain text in, scrambled fixed-length string out. 
Cannot be reversed back to the original.

## Hashing vs Encryption
- Encryption: two-way (can decrypt with a key)
- Hashing: one-way (never reversible) — correct choice for passwords

## Why bcrypt specifically
- Deliberately slow, resisting brute-force guessing attacks
- Automatically generates a random "salt" per password, so identical 
  passwords produce different hashes — defeats rainbow table attacks
- Salt rounds (commonly 10) control how slow/secure the hash is

## How login actually works without reversing the hash
Login doesn't decrypt anything. It re-hashes the freshly typed password and 
uses bcrypt.compare() to check if it matches the stored hash.

## Key methods
- bcrypt.hash(plainPassword, saltRounds) → returns a hashed string
- bcrypt.compare(plainPassword, storedHash) → returns true/false

## How it fits into Decision Journal
Tomorrow's User model will store passwords using bcrypt.hash() during signup, 
and use bcrypt.compare() during login — never storing or checking plain text.
