# Day 81 — Loading & Error States

## The problems
Repeated loading/error code per page, a failed action hiding the whole list,
"Failed to fetch" messages, no retry, blank screen on render crash, stale
responses overwriting new ones while typing.

## Load errors vs action errors
Load error (nothing to show) → full-area message + Try again.
Action error (page already has data) → small message, content stays visible.

## Keep data while refetching
Show the loading screen only when isLoading && !data.

## Custom hooks
A function starting with "use" that calls other hooks; shares stateful logic.
useFetch(fetcher, deps) returns { data, setData, error, isLoading, reload }.

## Race conditions
useEffect cleanup sets ignore = true for the previous request, so a late
response is discarded.

## Error boundaries
Class components (getDerivedStateFromError + componentDidCatch). Catch RENDER
errors in children only — not event handlers or async code. Wrapped around
<Outlet /> with key={pathname} so navigating resets the error.

## Network errors
apiFetch catches fetch's TypeError and throws a readable message.

## Gotchas
Primitive values in deps (objects/arrays cause infinite refetch loops).
Hooks before early returns. Functional state updates (setX(prev => ...)).

## How it fits into Decision Journal
Every page now behaves consistently when loading, failing or crashing, and
users can retry without refreshing.
