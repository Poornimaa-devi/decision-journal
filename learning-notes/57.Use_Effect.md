# Day 57 — useEffect

## The problem useEffect solves
Code that causes side effects (like fetching data) can't run directly in a 
component's function body — it would re-run on every render, potentially 
causing infinite loops if it also updates state.

## Syntax
useEffect(() => { /* effect code */ }, [dependencies]);

## Dependency array behavior
- No array: runs after EVERY render
- Empty array []: runs ONCE, after the first render only
- [value]: runs after first render, and again whenever `value` changes

## Cleanup functions
useEffect(() => {
  // setup code
  return () => { /* cleanup code, runs before next effect or on unmount */ };
}, []);

## How it fits into Decision Journal
useEffect with [] will be used (Day 58) to fetch the real goals list from 
the Express backend exactly once, when the Dashboard/App component first 
loads — replacing the current hardcoded useState array.
