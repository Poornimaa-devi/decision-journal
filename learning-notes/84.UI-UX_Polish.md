# Day 84 — UI/UX Polish

## Visual hierarchy
Size, weight, color and de-emphasis guide the eye. Completed goals are muted
and struck through; priority and status use badges.

## Accessibility rules applied
- Never rely on color alone: badges always contain text
- Text contrast of at least 4.5:1 (WCAG) for normal text
- Semantic HTML: article, section, main, nav with aria-label
- Skip-to-content link for keyboard users
- aria-label on progress bars

## Destructive actions
Inline two-step confirm using local state (confirmingDelete). Alternative:
immediate delete with an Undo toast.

## Two kinds of empty state
No data at all → explain and guide. Data hidden by filters → say nothing
matches and offer Clear filters.

## Page titles
usePageTitle(title) sets document.title in an effect; SPAs don't change it
automatically. Also fix the default <title> in index.html.

## Gotchas
Hooks before early returns; class names must match the CSS exactly;
data-* booleans render as strings; summary stats describe the filtered list.

## How it fits into Decision Journal
The app now communicates clearly: what matters is visible at a glance, risky
actions need confirmation, and empty or filtered views explain themselves.
