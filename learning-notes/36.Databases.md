# Day 36 — Databases (SQL vs NoSQL)

## What is a database?
Organized, permanent storage for data on disk, separate from a program's memory (RAM), 
that lets you query/search data without writing all the logic yourself.

## Why does my project need one?
Currently `goalController.js` uses `let goals = [...]` — a plain JS array in RAM. 
This data disappears every time the server restarts. A database persists data on disk.

## SQL Databases
- Structured into tables with fixed columns (schema)
- Every row must follow the same structure
- Relationships between tables enforced via foreign keys
- Examples: MySQL, PostgreSQL

## NoSQL Databases (MongoDB)
- Structured into collections of documents (JSON-like objects)
- Documents in the same collection can have different fields
- Looser relationships between collections
- Examples: MongoDB

## SQL vs MongoDB — Key Differences
| SQL | MongoDB |
|-----|---------|
| Tables & rows | Collections & documents |
| Fixed schema | Flexible schema |
| Strong relationships (JOINs) | Manual references |

## Why MongoDB fits Decision Journal
Decisions, goals, and reflections will likely evolve in shape as features grow 
(Phase 10-11). MongoDB documents are naturally close to JS objects, making the 
transition from in-memory arrays to a real database smoother.

## Mental Model
Controller → Mongoose Model → MongoDB (on disk) → survives restart, scales
