# Day 67 — Goals (Linking Goals to Decisions)

## Reference vs embedding
- Embedding: copy related data inside the document (can go stale)
- Referencing: store only the related document's _id (single source of truth)
Decision Journal uses referencing: Goal stores a Decision's _id.

## Schema syntax
decision: { type: mongoose.Schema.Types.ObjectId, ref: "Decision", default: null }
- ref must exactly match the model name ("Decision")
- default null makes the link optional

## populate()
Goal.find().populate("decision", "title") replaces the stored ID with the
actual linked document (only the fields listed). MongoDB still stores just
the ID; populate does the lookup at query time.

## Consistency across endpoints
Populate in get, create, AND update responses — React replaces state with
server responses (Days 60-61), so every endpoint must return the same shape.

## Gotchas
- Empty string "" as an ObjectId causes a cast error; send undefined instead
- Deleting a referenced document leaves a dangling ID (populate returns null);
  MongoDB doesn't enforce foreign keys

## How it fits into Decision Journal
Goals can now be traced back to the decision that produced them, which is
the core relationship of the whole app.
