# Day 61 — Updating Data (Real PATCH Requests)

## Why completed state moved from GoalCard to App.jsx
GoalCard's own local state (Day 54) had no connection to the real database 
and no way to inform App.jsx of changes. Lifting state up (Day 56 concept) 
makes App.jsx the single source of truth, matching MongoDB.

## PATCH fetch pattern
fetch(`url/${id}`, { method: "PATCH", headers: {...}, body: JSON.stringify({ 
  onlyTheChangedField: newValue 
}) })
Only send the field(s) actually changing — backend's findByIdAndUpdate 
handles partial updates correctly.

## Updating one item in an array of state
goals.map((g) => (g._id === goalId ? updatedGoal : g))
Creates a new array; replaces only the matching item, leaves others untouched.

## GoalCard is now a "dumb"/presentational component
It no longer owns any state — just displays props and calls functions 
passed from its parent. All real logic lives in App.jsx.

## How it fits into Decision Journal
Marking a goal complete now genuinely persists to MongoDB, confirmed via 
page refresh and Atlas — matching the same real-CRUD pattern used for 
creating goals (Day 60).
