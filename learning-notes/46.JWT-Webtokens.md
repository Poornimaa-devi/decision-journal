# Day 46 — JWT (JSON Web Tokens)

## Three parts of a JWT
Header (algorithm info) . Payload (your data) . Signature (tamper-proof check)

## JWTs are encoded, NOT encrypted
Anyone can read the header/payload (just Base64). Never store sensitive data 
(passwords, etc.) inside a JWT. The signature only proves it hasn't been 
tampered with — it doesn't hide the contents.

## Signing vs Verifying
- jwt.sign(payload, secret, options) → creates a token (at login)
- jwt.verify(token, secret) → checks validity, returns original payload 
  (on every protected request)

## Secret key
Must be long, random, stored in .env — never hardcoded or committed. If 
leaked, anyone could forge valid tokens for any user.

## Expiration
Tokens should include expiresIn (e.g. "1d") to limit damage if a token 
is ever stolen — this is also why JWT logout is harder than session logout, 
since the server can't instantly "delete" a token like it can a session.

## How it fits into Decision Journal
Day 48's login endpoint will use jwt.sign() to issue a token after verifying 
a user's password. Day 47's middleware will use jwt.verify() to protect 
routes going forward.
