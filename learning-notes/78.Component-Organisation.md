# Day 78 — React Component Organization

## The problem
Token pasted in four files, base URL hardcoded everywhere, fetch boilerplate
copied into every function, 20+ components in one flat folder.

## Separation of concerns (frontend)
- Components: what the user sees
- api/: how we talk to the server
- config.js: values that change per environment
Mirrors the backend split (routes / controllers / .env).

## API client
apiFetch(path, options) adds base URL, auth + JSON headers, checks response.ok
and parses JSON. Resource files (goals.js, decisions.js) wrap it in named
functions: getGoals(), createGoal(goal), updateGoal(id, updates), deleteGoal(id).

## Named vs default exports
export function x → import { x } from "./file"
export default X  → import X from "./file"
Mixing them up gives undefined or an export error.

## Folder structure by feature
components/goals, decisions, insights, profile, layout — related files together.

## Moving files safely
Drag in VS Code and accept "update imports"; check ../ depth afterwards; move
one folder at a time and test between moves.

## Secrets
config.js holds the temporary token → add to .gitignore, commit config.example.js.

## How it fits into Decision Journal
One place to change when the token expires or the app is deployed, and a
structure that stays readable as more features are added.
