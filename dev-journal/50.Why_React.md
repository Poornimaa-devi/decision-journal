# Day 50 — Why React?

## What I worked on
Studied why React exists — no coding today. Compared React's declarative 
approach against my existing vanilla JS imperative rendering code.

## What I learned
- The distinction between imperative and declarative programming styles
- Why manual DOM manipulation becomes harder to maintain as an app grows
- What a "component" means at a conceptual level, before writing any real ones

## Challenges
None coding-wise — conceptual day, revisiting my own Phase 2-3 code with 
new understanding.

## Key takeaway
My vanilla JS knowledge isn't wasted — it's exactly why I can appreciate 
what React automates. React doesn't replace JavaScript; it's a different, 
more scalable way of organizing UI code.
